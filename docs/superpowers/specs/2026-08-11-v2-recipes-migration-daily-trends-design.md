# 宝宝成长助手 V2：食谱、数据继承与生活趋势设计

## Objective

在不丢失现有 V1 本地数据的前提下发布 V2：扩充咀嚼练习期食谱、让旧宝宝和历史记录优先自动继承，并增加奶量、大小便及睡眠的按日横向对比图。

## Constraints

- 应用仍是静态、离线优先 PWA，不新增账号、服务器或云同步。
- 数据仍保存在当前浏览器的 IndexedDB 中。
- 同一 iPhone、同一 GitHub Pages 来源应无感读取原 V1 数据。
- iOS 不允许网页未经用户选择直接读取“文件”App 中的 JSON；本地数据库为空时，用户需选择一次 V1 备份文件。
- 必须兼容现有宝宝、作息、任务、奶量、排便、睡眠、菜单、偏好和其他历史记录。
- 不修改旧食谱 ID 或旧菜单中已保存的食谱引用。
- 不加入照片、商业化、账号或医学诊断功能。
- 实施时保留用户当前未提交的 `README.md` 与 `AGENTS.md`，不得纳入本功能提交。

## Current State

- IndexedDB 数据库名为 `babyGrowthAssistantV1`，schema version 为 1。
- 启动时若 `babies` 为空，会直接显示创建宝宝页面。
- 设置页支持 V1 JSON 全量导出和覆盖导入。
- 共 600 道内置食谱，每个辅食阶段 120 道；咀嚼练习期存在较多组合型变化，实际使用重复感明显。
- 已记录 milk、stool、sleep 等数据；没有独立的小便类型。
- 成长页已有身高、体重折线图，但没有按日生活指标聚合。

## Architecture

V2 采用渐进升级，不新建 `babyGrowthAssistantV2` 数据库。本次新增内容可复用现有 stores，因此保持 IndexedDB schema version 为 1，避免旧静态版本因数据库版本过高而无法打开。应用在完整校验现有数据后，通过 `appSettings.dataVersion=2` 标记业务数据版本；缺失的新字段在读取层使用兼容默认值，不批量重写历史。业务模块拆分为：

1. 数据迁移模块：检测现有数据、执行结构升级、验证迁移计数及处理空数据库恢复。
2. 食谱目录模块：承载扩充后的食谱元数据、筛选和菜单形态轮换。
3. 每日统计模块：将原始记录和跨日睡眠聚合为日指标。
4. 趋势图 UI：以单图切换方式展示睡眠、奶量、大便和小便。

各模块通过纯数据接口连接，迁移、聚合与食谱筛选均可脱离 DOM 单独测试。

## V1 Data Inheritance and Recovery

### Startup flow

1. 按原名称和 schema version 打开 `babyGrowthAssistantV1` 数据库。
2. 读取 `babies`。
3. 若已有宝宝，直接加载应用，并对缺少的 V2 字段使用兼容默认值；不显示创建宝宝页面。
4. 若数据库为空，显示恢复优先的空状态页：
   - 主操作：恢复 V1 备份。
   - 次操作：新建宝宝。
5. 用户选择 V1 JSON 后，先完成格式、引用关系和计数校验。
6. 仅当当前数据库仍为空时，直接全量导入；导入完成后显示恢复的宝宝数和记录数，并进入原宝宝首页。
7. 若当前已有数据，不允许静默覆盖，回到现有的明确确认导入流程。

### Compatibility rules

- 保留所有旧记录的 ID、babyId、时间和状态。
- 旧排便数据继续有效；V2 每日大便统计按其数值累计。
- 旧食谱和旧菜单可在缺少 V2 元数据时降级展示。
- 新增字段只补默认值，不反向改写业务历史。
- 完整校验通过后再写入 `appSettings.dataVersion=2`；失败时不改变业务版本标记或历史数据。
- V1 JSON 是最终回滚点；实现和发布前提醒用户保留备份。

## Chewing-stage Recipe Expansion

### Scope

- 将 `stage4` 咀嚼练习期从约 120 道扩充到约 300 道。
- 同时覆盖手指食物和颗粒主餐。
- 限制仅替换食材名称而产生的高重复组合。

### Difficulty levels

- `beginner-chewing`：软烂小块，可用牙龈处理，入口后容易散开。
- `advanced-chewing`：颗粒更明显，需要主动咬断与反复咀嚼，但避免硬、圆、滑和难吞咽形态。

### Categories

- 手指食物：软蔬菜条、蒸糕、软饼、饭团、薯条状食物。
- 颗粒主餐：焖饭、烩饭、软面、意面、疙瘩汤。
- 包馅类：小饺子、小馄饨、软包。
- 蛋白质类：肉丸、鱼饼、蒸肉饼、豆腐块。
- 早餐和主食：燕麦饼、蛋饼、发糕、软吐司搭配。
- 混合餐：谷物、蔬菜与肉蛋组成的完整一餐。

### Required recipe fields

每道新增食谱必须包含：

- 唯一且稳定的 ID。
- 名称、食材与明确用量。
- 分步骤做法。
- 建议切割尺寸。
- 软硬判断提示。
- 初级或进阶咀嚼等级。
- 是否属于手指食物。
- 常见过敏原列表。
- 可替换食材。
- 建议餐次。
- 是否适合冷冻保存。
- 原有 staple、texture、group、stage 和 stageName 等菜单字段。

### Menu and UI behavior

- 食谱页增加“初级咀嚼”“进阶咀嚼”“手指食物”筛选。
- 详情页展示制作步骤、尺寸、软硬、过敏原、替换和冷冻信息。
- 菜单生成继续执行忌口、收藏、不喜欢和阶段过滤。
- 菜单轮换优先避免连续相同形态，例如连续两餐都是饭类或软饼。
- 旧菜单中的 recipeId 不重写；若找不到扩展元数据，使用旧名称和分组安全降级。

## Daily Lifestyle Trends

### Metrics

- `sleep`：每日实际睡眠分钟数，展示为小时。
- `milk`：每日奶量记录数值求和，单位 ml。
- `stool`：每日大便次数；旧记录按 value 累计，V2 快捷记录每条默认 value=1。
- `urine`：每日小便次数；V2 快捷记录每条默认 value=1。

### Aggregation rules

- 使用宝宝本地时区的自然日分组。
- 跨午夜睡眠按各自然日实际重叠分钟数拆分。
- 记录存在但值为 0 与当天完全没有记录必须在模型中区分，例如使用 `hasData`。
- 返回连续日期序列，包含无记录日期，以保持横轴完整。
- 支持最近 7、14、30 天；默认 7 天。
- 计算当前周期平均值和前一相同长度周期的变化量。

### UI

- 成长页新增“生活趋势”。
- 采用单图切换布局：睡眠、奶量、大便、小便四个指标。
- 时间范围可切换 7 天、14 天和 30 天。
- 默认显示“睡眠 + 最近 7 天”。
- 使用大尺寸柱状图；横轴显示日期，柱子点击或聚焦后显示完整日期和数值。
- 14 天与 30 天降低日期标签密度，避免 320–430px iPhone 屏幕重叠。
- 图表下显示平均值和与前一周期的差异。
- 无数据日使用不同的空态标记，不将缺失误表达为真实 0。
- 不输出医学正常值、异常判断或健康结论。

### Recording changes

- 快捷记录中增加“小便”。
- 大便和小便均为一次点击记录一次，默认 value=1，并允许编辑时间与备注。
- 奶量继续由用户填写 ml。
- 睡眠继续通过计时、结束和补记产生。

## Error Handling

- 备份无法解析或不属于本应用：不写入数据库，显示明确错误。
- 备份引用关系或数据类型错误：导入整体失败，不进行部分写入。
- 数据兼容检查失败：保留原记录与 `dataVersion`，提示继续使用备份恢复。
- 食谱缺少扩展字段：使用旧展示方式，不阻止菜单打开。
- 趋势记录不足：显示已有柱子和空日期，不要求至少两个数据点。
- Service Worker 必须使用新的独立缓存版本并缓存所有新增模块。

## Verification

### Migration

- 有 V1 宝宝数据时，V2 启动不显示创建宝宝页。
- 空数据库可选择 V1 JSON 并直接恢复，随后进入原宝宝首页。
- 导入前后逐 store 比较记录数，并验证关键引用和 activeBabyId。
- 已有数据时不会静默覆盖。
- 损坏或不兼容备份不会产生部分写入。

### Recipes

- stage4 数量约为 300，ID 唯一且所有必填字段完整。
- 分类与咀嚼等级覆盖达到设计要求。
- 对名称、核心食材、步骤和形态组合做重复度检查，阻止大量模板化重复。
- 排除食材、阶段、收藏和不喜欢逻辑继续通过原测试。
- 菜单连续形态轮换有确定性测试。

### Trends

- 8 月 1 日睡眠 11 小时、8 月 2 日睡眠 12 小时能准确显示。
- 跨午夜睡眠正确拆分到两个自然日。
- 同日多笔奶量正确求和。
- 旧大便 value 与 V2 单次大便记录均正确累计。
- 小便记录按日计数。
- 7、14、30 天序列、平均值和前周期变化正确。
- 缺失数据与真实 0 可区分。
- 320、375、390、430px 宽度下图表标签和控制不重叠。

### Regression

- 完整自动化测试通过。
- V1 导出、导入、清空和通知等现有功能不回归。
- PWA 离线缓存与更新提示验证通过。

## Rollback

- 发布前保留用户现有 V1 JSON 备份。
- 开发在独立分支或 worktree 中进行；验证失败可丢弃该分支。
- 本次保持 schema version 为 1，不删除旧字段或 store；旧静态版本仍能打开原数据库。
- 若线上 V2 出现问题，可回退静态资源版本；原数据库中的 V1 数据仍可由旧代码读取。
- 若本地数据意外丢失，可清空空白数据库后重新选择 V1 JSON 恢复。

## Out of Scope

- 账号、登录、云同步和跨设备自动同步。
- 未经用户选择自动读取 iPhone“文件”App 中的备份。
- 医疗诊断、营养摄入达标判断或发育异常提醒。
- 照片上传和识别。
- 除咀嚼练习期外其他阶段的大规模扩充。
