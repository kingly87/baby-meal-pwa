# 睡眠驱动作息与移动端信息优化设计

日期：2026-07-23  
状态：等待用户复核

## Objective

解决手机端今日事项操作凌乱、睡眠结束不能驱动后续作息，以及菜单展示内部占位名称和信息不足的问题。

## Scope

本次只调整以下区域：

1. 今日首页当前事项操作区。
2. 记录页睡眠计时区。
3. 睡眠结束与当日作息任务之间的联动。
4. 周菜单菜名、摘要和状态展示。

不修改食谱安全过滤、多宝宝隔离、备份格式、照片、云同步或商业化能力。

## Sleep-driven Schedule

### 睡眠类型

睡眠记录必须包含明确类型：

- `night`：夜间睡眠。
- `nap`：午间或白天小睡。

补记睡眠时由用户选择类型。实时开始睡眠时也允许选择，默认根据当前时间建议类型，但最终以保存的类型为准，不依赖模糊推断。

### 夜间睡眠结束

夜间睡眠结束时间视为当天实际起床时间：

- 将当天 `wake` 任务标记为已完成，`actualAt` 等于睡眠结束时间。
- 已完成或已跳过的历史任务保持不变。
- 从起床任务开始，按照当前作息模板重新计算未完成任务。
- 示例：睡眠在 `07:00` 结束，模板为起床后 20 分钟喝奶，则早间喝奶调整为 `07:20`。

如果当天已存在更晚的人工调整，用户主动设置的 `adjusted` 事项不被自动覆盖。

### 午间小睡结束

午间小睡结束后，以结束时间作为下一餐的计算锚点：

- 找到当天尚未完成的下一项辅食任务。
- 使用作息模板中“小睡后到辅食”的间隔；V1 默认 120 分钟。
- 示例：小睡在 `14:00` 结束，下一次辅食调整为 `16:00`。
- 后续尚未完成的事项从新辅食时间继续顺延。
- 已完成、已跳过和人工调整的事项保持不变。

如果当天没有未完成的辅食任务，只保存睡眠，不额外创建临时任务。

### 补记与修正

新增、结束或编辑睡眠记录后都重新执行上述联动，确保补记 `07:00` 结束的夜间睡眠也能修正原本的 `08:20` 喝奶。

## Today Card

当前事项卡片采用明确的两级操作：

- 主按钮：`完成`，占主要宽度，默认按照实际完成时间顺延后续任务。
- 次入口：`更多操作`，打开底部对话框。

更多操作包含：

- `完成但保留后续时间`
- `调整当前时间`
- `跳过此事项`

所有操作项使用统一高度、圆角和宽度；危险性较高的“跳过”在视觉上弱化，不与主按钮争夺注意力。

## Sleep Controls

睡眠计时区只显示当前可执行的主操作：

- 未在睡眠：显示整行主按钮 `开始睡眠`。
- 正在睡眠：显示整行主按钮 `结束睡眠`。
- `补记睡眠` 始终作为下方次级文字按钮。

不再同时展示不可点击的灰色按钮。状态文字显示“尚未开始”或“已睡 X 分钟”。

## Meal Information

### 菜名清理

展示层移除菜名末尾的内部去重后缀：

- `·搭配2`
- `·搭配3`
- 以及其他 `·搭配数字`

底层 recipe ID 保持不变，不影响菜单替换、收藏或购物清单。

### 菜单卡片

每餐展示三层信息：

1. 清理后的菜名，例如“嫩豆腐土豆宝宝面”。
2. 实际食材与建议量，例如“嫩豆腐 15–30g · 土豆 20–35g”。
3. 主食/质地与适龄阶段，例如“宝宝面 · 家庭餐过渡期”。

状态使用独立标签：

- 计划中
- 已吃
- 已跳过

不再显示信息量较低的“豆腐 · 计划中”组合。

## Data and Compatibility

- 不修改现有食谱 ID 和周菜单 meal ID。
- 旧菜单中的带后缀菜名在渲染时清理，无需迁移 IndexedDB。
- 睡眠类型缺失的旧记录仅用于统计，不自动改写作息；用户编辑并选择类型后才触发联动。
- 所有自动调整都只作用于同一宝宝、同一自然日。

## Verification

自动测试至少覆盖：

- 夜间睡眠 `07:00` 结束后，喝奶变为 `07:20`。
- 午间小睡 `14:00` 结束后，下一辅食变为 `16:00`。
- 已完成、已跳过及人工调整任务不被覆盖。
- 补记或编辑睡眠也会重新计算。
- 今日卡片只展示“完成”和“更多操作”两个顶层按钮。
- 睡眠计时区不会同时展示可用和禁用的主按钮。
- 任意 `·搭配数字` 后缀都不会出现在菜单页面。
- 菜单卡片展示食材量、主食/质地、阶段和独立状态标签。
- 完整测试、移动端浏览器截图和控制台错误检查通过。

## Rollback

改动使用独立 Git 提交。若睡眠联动或移动端布局出现回归，可回退该提交；现有 IndexedDB 数据结构保持兼容，不需要回滚用户数据。
